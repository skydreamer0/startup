# 頁級 SPEC｜填寫範本與首兩片

## 每一頁要寫
- 名稱、版本、負責角色、入口、可觀察的成功終點。
- 現版證據、既有 Issue、允許改動檔案、不改的業務邊界。
- 主要資訊順序、互動狀態、寬窄版、是否 modal、鍵盤和觸控。
- 資料來源與權限，零／缺值、失敗、回復、重送；涉及寫入，寫清楚重複與回滾。
- 驗收編號、前置、動作、預期結果及實際收據；模擬／API＋PG／實頁／實機分列。

## A｜後台報表重試（#31／#199）
1. 切期間或篩選，畫面不把前一條件資料當現在；失權不回退舊值。
2. 區分真零、成功空、首次載入失敗、舊資料、重試中、恢復及再次失敗。
3. 連點、Enter／Space 只容一個在途唯讀請求；不送出外層表單。保留篩選及合理焦點。
4. 用同一版本做亮暗、長文、鍵盤、讀屏與實際請求計數。不改報表計算。

## B｜POS 手動貼碼（#31／#48／#49／#199）
1. 開窗時焦點合理；Esc 回入口；IME／掃碼尾碼不觸發背景搜尋、加車或付款。
2. 貼碼、檢視、明確查找及選候選分開。零／一／多筆、403、失回應、關窗後舊回應分開驗。
3. 初次掃碼及多筆候選不得默默選擇。不因視覺改動變更交易意圖、數量、庫存或付款。
4. 鍵盤與觸控須驗；以真實掃碼設備為另一門檻。接單失回應只能查回原結果，不在此片改交易引擎。

## 驗收收據格式
版本與實際 build｜環境及資料範圍｜案例和結果｜未測／阻擋原因｜實際請求／焦點／尺寸｜清理與回退｜獨立審查者。不得記入密碼、顧客真實資料或密鑰。
