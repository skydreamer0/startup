# 02_客群與需求驗證模板

## Metadata
| 欄位 | 內容 |
| --- | --- |
| Owner | Founder |
| Update Frequency | 每月一次；重大策略調整時即時更新 |
| Input From | 客戶訪談、競品研究、市場數據 |
| Output To | C_營運層、D_財務層、E_對外送件、F_執行與驗證 |


## 用途
系統化記錄客群分層、需求強度與付費意願證據，將訪談資料轉成可決策輸入。

## 適用時機
- 啟動前 30-60 天。
- 新通路或新 SKU 上線前。
- 回購率異常時做原因追查。

## 必填欄位
| 欄位 | 型別 | 必填 | 說明 |
| --- | --- | --- | --- |
| `segment_id` | string | 是 | 對應 `SegmentProfileV1.segment_id` |
| `segment_name` | string | 是 | 客群名稱 |
| `problem_statement` | string | 是 | 該客群主要痛點 |
| `urgency_score` | number | 是 | 1-5 分 |
| `willingness_to_pay` | number | 是 | 1-5 分 |
| 訪談樣本數 | number | 是 | 每分群至少 10 份 |
| 付費證據類型 | string | 是 | 預購/實購/口頭意願 |
| 反對意見摘要 | text | 是 | 阻礙成交主因 |

## 填寫規則
1. 每個分群至少記錄 10 份有效樣本。
2. 只接受可追溯訪談紀錄（日期、訪談者、來源）。
3. 付費意願必須配對至少一項具體行為證據。
4. 若樣本不足，標記資料風險級別。

## 輸出範例格式
```text
[分群檔案]
segment_id: SEG-XXX
segment_name: <名稱>
problem_statement: <痛點>
urgency_score: <1-5>
willingness_to_pay: <1-5>

[訪談證據]
訪談總數: <N>
有效樣本: <N>
主要痛點Top3:
1) <痛點>
2) <痛點>
3) <痛點>

[付費證據]
- 實際購買: <筆數>
- 預購承諾: <筆數>
- 反對主因: <摘要>
```

## 常見錯誤
- 將「有興趣」誤判為「有付費意願」。
- 分群太粗，導致需求行為混在一起。
- 訪談沒有標準問法，難以比較。

---

## 訪談問綱模板
1. 你最近一次遇到這個問題是什麼時候？
2. 你現在怎麼解決？成本是多少？
3. 若有更好的方案，你願意支付多少？
4. 你會因為哪些原因不買？
5. 你通常透過哪個渠道接收這類資訊？

```text
urgency_score: 5
willingness_to_pay: 4

[分群檔案B]
segment_id: SEG-VNM-002
segment_name: 越南新住民家庭
problem_statement: 家庭常備與照護商品選擇不透明，價格與品質難比較
urgency_score: 4
willingness_to_pay: 3

[分群檔案C]
segment_id: SEG-VNM-003
segment_name: 越南社群影響者/KOL節點
problem_statement: 缺乏可長期合作且合規的商品供應與內容支援
urgency_score: 3
willingness_to_pay: 3

[訪談證據目標]
訪談總數: 36
有效樣本: 30
來源分配: 實體店12 / 社群10 / LINE8
主要痛點Top3:
1) 不知道哪裡買到長期可得且價格合理的品項
2) 需要越語溝通與信任背書
3) 遇到處方相關服務時流程不清楚（需藥師/法顧確認）

[付費證據欄位]
- 實際購買: 先達成>=50筆首購
- 預購承諾: 目標>=20筆
- 反對主因: 價格敏感、等待時間、對流程不熟
```

### 初版訪談執行計畫（前4週）
1. 第1週：完成訪談問卷定稿與訪員訓練（中文/越文版本）。
2. 第2週：實體店與社群各完成至少10份訪談。
3. 第3週：LINE 私域補齊至少10份訪談並收集反對意見。
4. 第4週：輸出分群優先級與首波SKU建議清單。
