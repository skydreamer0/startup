# ADR-008: POS Standalone SPA Architecture

**Date:** 2026-05-16  
**Status:** Accepted  
**Branch:** feature/phase-9-pos

## Context

Phase 9 introduces a POS checkout UI for pharmacy front desks. The decision was whether to add POS screens inside the existing `admin-ui` SPA or build a dedicated SPA.

## Decisions

1. **pos-ui is a separate Vite SPA** (port 5174), independent of admin-ui bundle. Rationale: POS runs on kiosk hardware with different caching needs; admin bundle (~2MB) would bloat POS startup; deployment can be isolated per device.

2. **Shared backend API** — pos-ui and admin-ui call the same `/api/v1/admin/*` base URL with the same JWT auth. No separate backend for POS.

3. **ESC/POS buffer generated by backend** — receipt format logic is in `receipt.service.ts`, fully testable. Frontend only handles WebUSB transmission. Fallback: `window.print()` for browsers without WebUSB (iOS Safari).

4. **WALK_IN_CUSTOMER system record** — a seeded `Customer` with `phone='WALK_IN'` per tenant avoids making `Order.customerId` nullable (which would be a breaking migration across all existing orders).

5. **salesStaffId independent of shiftId.staffId** — shift opener and checkout clerk are separate fields on `Order`, enabling multi-clerk rotation within one shift and accurate per-staff revenue attribution.

6. **Background Sync offline queue** — 50-transaction IndexedDB limit with manual conflict resolution when stock was depleted by another terminal during offline period.

## Consequences

- pos-ui needs its own `npm install` and `npm run dev` step (port 5174).
- CSS design tokens are duplicated from admin-ui/src/index.css — acceptable for MVP; refactor to shared package if theme drift becomes an issue.
- WebUSB requires Chrome + HTTPS (or localhost) — document in deployment guide.
- TypeScript WebUSB types not available in standard DOM lib — use type assertions (`navigator as unknown as { usb: any }`).
