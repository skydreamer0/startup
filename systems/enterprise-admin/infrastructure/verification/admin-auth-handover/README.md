## Reproduced source defects

Actual React AuthProvider tests against the base produce three failures: a delayed profile resurrects a logged-out actor; an old profile failure clears a newer actor's token pair; a delayed login stores credentials after logout. Actual Axios adapter tests produce three additional failures: an old refresh success replaces the newer token, an old refresh failure clears it, and an old401 refreshes with the newer actor's credential and replays an earlier request. These are synthetic transport-boundary controls, not native API/PG evidence.

A real QueryClient negative restores the old Provider and proves logout does not cancel pending cache work or remove unscoped cached data. The correction uses a process-local identity generation, aborts superseded profile/login requests, preserves LoginPage's own pending/error state, and clears the shared QueryClient at handover. Old results, errors and refreshes cannot mutate the new session. Refresh snapshots remain in a private WeakMap rather than Axios's serializable config. Session endpoint401s are returned directly rather than automatically refreshing/replaying login/logout. Logout captures the current credential synchronously for its existing audit request before local removal. This does not revoke already-issued server JWTs or cancel a committed server write.
